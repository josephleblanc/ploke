Shows all syntax edges for the target item and, when available, call graph and proof graph context for the same item. Useful for discovering nearby code items, outgoing calls, incoming callers, bounded multi-hop call paths, reachable proof-annotated effects, and proof blockers.

Use this tool when you know the file path, item name, node kind, and crate-relative module path. `module_path` must start with `crate`, for example `crate` or `crate::module::submodule`; it is not the Cargo package name and it does not include the target item name.

If the module path is unknown, use `request_code_context`, `read_file`, or `list_dir` first. On success, the returned `node_info.canon_path` includes the item name and can be used as the `canon` value for `apply_code_edit`.

When call graph data is available, `node_info` includes `call_context`, bounded call path summaries, `call_impact`, `call_reach`, `call_reach_effects`, `external_summary_needs`, `runtime_dispatch_needs`, `local_bindings`, `local_binding_edges`, `returned_call_binding_flows`, `returned_future_flows`, and `returned_future_execution_flows`. Use `call_reach_effects` for proof-annotated source/sink questions; effect rows preserve the original targetless callsite payload and do not fabricate local call edges for external or unsupported frontier calls. Pass `allowed_effects` to request `node_info.call_effect_policy_violations`, which reports reachable effect seeds outside that explicit allowlist. Use `node_info.runtime_dispatch_needs` to find reachable unsupported callsites with active `dynamic_dispatch_unbounded` proof blockers.

Use `node_info.local_bindings` and `node_info.local_binding_edges` to explain exact local callable proof such as initialized function-item bindings, aliases, constructed field projections, and argument-to-parameter carrier edges. These rows explain already-admitted calls; they do not authorize additional traversal by themselves. Use `node_info.returned_call_binding_flows`, `node_info.returned_future_flows`, and `node_info.returned_future_execution_flows` for returned-callable and returned-future proof paths. Returned future rows are explanatory proof payloads and must not be treated as ordinary local call-path edges unless a separate resolved call edge is present.
