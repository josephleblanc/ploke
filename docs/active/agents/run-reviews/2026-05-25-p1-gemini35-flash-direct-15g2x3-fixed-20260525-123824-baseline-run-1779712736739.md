The production patch is directionally useful. It replaces the direct matcher
`replace_with_captures_at` call in `Replacer::replace_all` with a local helper
that stops when `m.start() >= limit` and only appends through the original
range end. That matches the issue's core requirement: replacement iteration
must not consume matches from the look-ahead buffer.

Benchmark usefulness remains incomplete. The gold patch names the helper
`replace_with_captures_in_context`, passes the original `range`, and adds
integration tests for issues 2095 and 2208. The submitted patch uses a simpler
`limit` helper and adds only:

```text

```

That test checks line selection after replacement, but not the reported
look-around/capture-group regression.
