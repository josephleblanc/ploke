## Non-Blocking Bugs To File

- Observe-child sidecar evidence loss: `runner-result.json` and
  `results/<runtime>.json` are insufficient as review artifacts even when the
  channel terminal message contains the registration, record path, and metrics.
- Final-cargo selection mismatch: the final cargo call was focused
  `grep-searcher` and did not cover the changed printer files. The UI/final
  response guard should prevent treating the last successful cargo result as
  patch validation when `covers_changed_files` is false.
- Cargo package argument loss: trace call 54 requested package
  `grep-printer`, but validation audit records `package: null` for the
  successful root-manifest test. The audit should preserve both requested
  package and resolved manifest.
- Read path corruption: the failed `read_file` path had a duplicated
  `p1-gemini35-gemini35...` segment. The model recovered, but the path builder
  or prompt/path copy surface needs inspection.
- `insert_rust_item` inline-module miss: insertion into `crate::standard::tests`
  failed even though nearby graph context identified the tests module. This is
  recoverable with `non_semantic_patch`, but it is a tool ergonomics issue.
- Protocol adjudication reliability: node stderr shows a malformed
  `tool_call_review[1]` adjudication JSON retry and a later provider 429. The
  protocol artifact exists, so this did not block the run, but it should be
  tracked if recurrent.
- Patch polish risk: the exported production change in `util.rs` removed the
  `replace_all` doc comment and left visible indentation oddness around
  `pub fn replace_all`; there is no `cargo fmt` evidence.
