# Typestate transition and eval-store schema ledger

**Status:** pre-run worksheet / source-backed starter inventory.
**Campaign:** `p1-gated-parent-3g1x3-p3-20260630-174316`
**Purpose:** record which normalized DB relations should be written or read at each Prototype 1 typestate phase, then verify them with `walk show` and `walk db_query` during the live run.

## Ground rules

- All 65 implemented eval-store relations listed here are defined with `define_eval_schema!` under `crates/ploke-eval/src/cli/prototype1_state/eval_store/`.
- Owner DB reads in the live typestate path are currently limited mostly to schema existence/drift checks and idempotence/conflict checks inside writers. The authority-bearing live gates still read filesystem/History/Channel/MessageBox/artifact surfaces unless explicitly migrated.
- `walk db_query` is the operator proof surface for DB facts. Do not inspect the SQLite file directly.
- `eval_record_ref` is provenance only. It is not a substitute for normalized rows.
